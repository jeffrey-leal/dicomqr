# dicomqr

A Fyne-based Windows GUI application for querying and retrieving DICOM files from a PACS server.

## Build

Requires CGO and the mingw64 GCC toolchain. **Must be built from an MSYS2 MinGW64 terminal.**

JPEG 2000 decoding (`-tags openjpeg`) requires the OpenJPEG library, and JPEG Lossless decoding (`-tags jpeglossless`) requires libjpeg-turbo 3.x, each installed once with:
```bash
pacman -S --needed mingw-w64-x86_64-openjpeg2
pacman -S --needed mingw-w64-x86_64-libjpeg-turbo
```
Release builds enable both tags (`-tags "openjpeg jpeglossless"`; libopenjp2 and libjpeg are statically linked — single self-contained exe). Omitting a tag still builds; the corresponding files then report "support not built in" and suggest the external viewer.

All builds must pass `-extldflags=-static` so GCC links its own runtime (libwinpthread, libgcc) statically; without it the exe imports `libwinpthread-1.dll` and fails to start on machines without MSYS2.

Open MSYS2 MinGW64, then:

```bash
export PATH="/c/Program Files/Go/bin:$PATH"
cd /c/Users/jeffr/source/repos/dicomqr
```

Release build:
```bash
CGO_ENABLED=1 CC=/c/msys64/mingw64/bin/gcc.exe GOAMD64=v3 \
  go build -tags "openjpeg jpeglossless" -ldflags="-s -w -H windowsgui -extldflags=-static -X main.buildDate=$(date +%Y-%m-%d)" -o dicomqr.exe .
```

Development build (with debug info):
```bash
CGO_ENABLED=1 CC=/c/msys64/mingw64/bin/gcc.exe \
  go build -tags "openjpeg jpeglossless" -ldflags="-extldflags=-static -X main.buildDate=$(date +%Y-%m-%d)" -o dicomqr.exe .
```

| `modifyprofile.go` | Modification (de-identification) profiles — `ModProfile` + `TagConfig`, load/first-run seeding of `~/.dicomqr/profiles.json` and `tags.json`, base-chain resolution, tag parsing/display names; `modProfileTargetSyntax` maps the dicomqr-only `transfersyntax` field (same `explicit-le`/`implicit-le` tokens as the server profile) to the UID exports are written in, and the `tsExportLabel*` constants keep the profile editor and the Modification dialog naming it identically |
| `modifyengine.go` | De-identification engine ported from dicomtool `modify` (identical semantics): set/remove/keep, DOB mask, UID suffix/remap, date shifting (`shiftdays` — DA/DT at any depth, PatientBirthDate excluded), private-tag removal, fixvr, per-modality overrides; `runModification` worker pool writes to an export folder using the PHI-safe layout from `exportRelPaths` (original patient/study folder names never reused: study runs keep series subfolders only, patient runs get generic `study-NN`); `runModificationToZip` runs the same pipeline into a single zip archive (parallel modify, serialized entry writes; temp-file + rename so a failed/empty run leaves no archive). One step has no dicomtool equivalent: an optional **transfer syntax conversion** (`targetTS`), applied **last** because decompression rewrites the attributes describing the pixels it produces, and profile-wide (never per modality). A source whose pixel data has no built-in decoder fails that file rather than exporting it in an unrequested syntax. `modifyWriteOpts` relaxes write verification to `SkipVRVerification`+`SkipValueTypeVerification` whenever a conversion is requested — emitting Explicit VR for elements parsed under Implicit VR would otherwise fail files that write fine untouched |
| `modifydialog.go` | Modification confirmation dialog (editable set values and options, removal-tag list), export destination (persistent default output folder used directly — picker only when unset, first choice saved as the default, Change… = single-run override, always outside the download folder; editable PHI-safe export folder name pre-filled with profile + timestamp; Patient Name set field auto-fills Patient ID and the export name until edited directly; Zip export checkbox writes a single `<export name>.zip` instead of a folder and is pre-checked from the profile's `zip` field — per-run override, never written back; Output transfer syntax select is seeded from the profile's `transfersyntax` the same way), background run with progress/cancel/summary. A run that ends with any failed file **replaces** the progress dialog with `showModificationFailureDialog` — files missing from an export are invisible in a summary line, and a conversion that could not run is exactly when the user must know the export is incomplete |
| `modprofileeditor.go` | Modification-profile editor (Preferences > Modification & Export) — a **top-level window** (640×760, movable and resizable; Fyne dialogs are canvas overlays and can be neither), opened through `openOwnedWindow` keyed per profile (so a second Edit raises rather than duplicates) and owned by + blocking the Preferences window, which therefore takes it along when it closes — an orphan would save into a discarded pending map. Single-column layout, sections stacked: name/base, Tag rules, Options, File filters, per-modality overrides. Exposes every engine-honored field: core `ModProfile` fields with alias-aware validation and base-cycle checks, ignoretype/ignoremodality filters (comma-separated entries), and a per-modality override list whose nested sub-editor edits only the modality-specific fields — the three tag lists plus keepprivate (which is meaningful only there; the top-level flag is inert, so it has no control and is preserved like dicomdir/verbose). Output transfer syntax and Zip export are profile-wide because the engine reads them once per run, not per file. The scalar options (dob/uid/shiftdays/fixvr/noprivate) are profile-wide by product decision even though the engine would honor them per modality — a hand-authored per-modality scalar is preserved and disclosed in the sub-editor's italic note, never silently dropped. The shared `modProfileFieldSet` plus the scalar validators in modifyprofile.go keep validation identical across the main editor, the sub-editor and the Modification dialog; `validate()` on both editor structs is the whole save path, driven directly by tests |
| `tagviewer.go` | Tag-level review window (Local Browse right-click → View Tags) — port of dicomhdr's tag tree: Patient → Study → Series → Instance → elements with search, dictionary hover tooltips, settings-driven styling (private italics, malformed colour, tag profile colours; live-refreshes open windows on preference changes), copy actions, concurrent incremental load, instance right-click Export Tags… (single-instance CSV/JSON via export.go) |
| `tagdictionary.go` | DICOM dictionary enumeration for the tag picker — suyashkumar's `tagDict` is unexported with no iterator, so `dictionaryTags()` probes `tag.Find` across `dicomStandardGroups` (76 even groups), in parallel because `Find` allocates an error on each of the ~5M misses (~0.3 s warm, cached by `sync.Once`, pre-warmed when the profile editor opens). Drops the "Generic Group Length" entries `Find` synthesises for element 0000 of every even group. `TestDictionaryGroupsCoverLibrary` greps the library source so a group added by an upgrade fails a test instead of vanishing from the picker |
| `tagpicker.go` | Tag picker **window** (Choose… beside Remove tags / Keep tags in both profile editors) — opened via `openOwnedWindow` owned by the editor and **blocking** it (the picker snapshots the field's text on open, so edits behind it would be overwritten by Apply); deliberately unkeyed, since blocking already makes a second picker unreachable and a key shared across two editors would raise the wrong window. dictionary as a group tree with per-tag checkboxes, search over name/keyword/number, Hide retired. Opens pre-checked from the field's current entries, and since that selection would be invisible behind 76 collapsed groups it opens in **Show selected only** mode whenever the field is non-empty; group headers carry a per-group tally (`selByGroup`, maintained incrementally by `setSelected`). Tags a profile names but the library's dictionary lacks (the shipped base-deident has three) have no row — counted separately by `selectedUnknown` and written back untouched. **Checkboxes on tags only, never groups** (no group wildcard exists in the profile format; whole-group removal would expand to hundreds of entries and destroy 0028/0008); bulk select only over an active search. `mergeTagSelection` **merges into the existing lines rather than regenerating them** — a surviving entry keeps its alias or zero-stripped spelling, because `mergeModProfiles` cancels Keep against Removes by literal string equality; only new tags are appended as `GGGG,EEEE`. The editor's Remove/Keep entries are **display-normalised**: `decorateTagList` renders every resolvable entry as zero-padded `GGGG,EEEE  Name` regardless of stored spelling (two-space delimiter so single-space aliases survive). Neither the padding nor the name may reach profiles.json — `checkTagLines` takes the field set's `origRemoves`/`origKeep` and maps each line back to the spelling the profile already used, storing new tags as typed. `strippedTagLines` must return nil (not an empty slice) or Preferences' DeepEqual change-detection rewrites the file on every Apply |
| `tagprofiles.go` | Tag Highlights/Tag Profiles support (from dicomhdr) — `TagProfile` with dicomhdr-compatible JSON wire format, `matchProfile`, tag list parsing, profile editor dialog, malformed-colour default |
| `importtab.go` | Import tab — scan external folder and copy selected files into the download folder |
| `worklist.go` | Worklist tab — Modality Worklist C-FIND with independent server selector |
| `viewer.go` | Internal image viewer, study overview grid, DICOM annotation overlay, thumbnail widget. Two navigation modes, decided by the series: **slice mode** (no multi-frame instance) keeps one slider position per image, over the flat `[]viewerSlice` (path + frame index) that `expandFrames` builds; **chapter mode** (any multi-frame instance) scopes the slider to one chapter and adds the cine transport and filmstrip. `parseDicomFile` (parse, no pixel decode) is split from `parsedDicom.frameState` (decode + render one frame) so a `dicomFileCache` — one per viewer window — parses each file once and decodes a single frame per navigation step; `imageViewport.setPlaybackFrame` is the cheap per-frame cine path that skips the annotation rebuild. All background→UI hand-offs go through `postUI` (= `fyne.Do`; tests substitute a serialising version, since Fyne's test driver has no UI thread). Labels that re-text at display rate (frame counter, W/L info, chapter label) are wrapped in `stableMin` — on Windows any canvas min-size change becomes `MoveWindow(repaint=TRUE)` on the whole OS frame, and at playback rate that storm flickers lines around the window |
| `chapters.go` | `chapter` — one SOP instance as an independently playable unit (frame count, label, cine timing). `scanChapters` builds them in the single header pass that already ordered the series; `anyMultiFrame` decides chapter mode. Labelling falls back ImageComments → ProtocolName → ViewCodeSequence → ultrasound region types (2D / Colour flow / PW / CW) → ImageType detail → SeriesDescription, skipping any candidate with no letter in it as an identifier. Cine timing (`cineFPS`, `cineBounce`, `cineLoopRange`) reads the five overlapping rate attributes in priority order, tolerating IS-stored values, and clamps everything |
| `cineplayer.go` | `cinePlayer` — ticker goroutine converting elapsed wall time into frame advances, gated on a readiness predicate so playback holds rather than outrunning the buffer. `cineStep` is the pure closed-form position arithmetic (wrap, sweep as a triangular wave) and is where the loop behaviour is tested |
| `clipbuffer.go` | `clipBuffer` — the active chapter's frames decoded across every core into memory (playback cannot decode on demand at 30 fps), colour converted to RGBA off the UI goroutine, capped by `clipBufferBudget` (384 MB) with truncation reported rather than treated as failure. One reporter goroutine publishes progress; the workers only count |
| `chapterstrip.go` | `chapterStrip` — the filmstrip: one tappable cell per chapter (middle-frame thumbnail, label, frame-count badge), decoded in parallel and box-filtered down to 84 px, posted to the UI by a single collector goroutine |
| `mrphases.go` | Multi-phase MR detection — a single-frame series whose instance-ordered slice locations repeat as K ≥ 2 identical runs (blocked or interleaved, one orientation) presents as K phases × N slices: slider spans one phase, Phase dropdown / P key toggles phases at the same slice keeping view and window. Structural detection (no tag identifies the axis reliably — the sample study's diffusion pair differs only in SequenceName); tags only label phases (echo/TE → sequence name → temporal position → acquisition number → ordinal). Sample-data hook: `DICOMQR_MRPHASE_SAMPLE=<folder> go test -run TestSampleMRPhaseSeries` |
| `windowplacement.go` | Opening geometry of the main window — Fyne exposes only `Resize` and `CenterOnScreen` (no position API, no screen-size API), so this asks Windows directly via `syscall`, as nvthreadctl.go does for NVAPI: `SPI_GETWORKAREA` for the taskbar-excluded desktop, `EnumWindows` filtered by our PID + title for the HWND Fyne never surfaces, then one `SetWindowPos`. All physical pixels — mixing them with Fyne's scaled units would misplace the window on a scaled display. `mainWindowPlacement` holds the arithmetic free of Windows calls so it is unit-tested: size = the window's **actual** `GetWindowRect` size unless settings hold none (then 60% × 80%), origin = the saved position or else vertically centred + `mainWindowLeftBias` of the slack on the left, then **clamped into the work area** — that clamp is why the size is always passed to `SetWindowPos` rather than `SWP_NOSIZE`. Position persists via `windowX`/`windowY`/`windowPosSaved` (physical pixels; Fyne cannot report a position, so it comes from `GetWindowRect` in the close intercept) while `windowWidth`/`windowHeight` stay Fyne's scaled units. Runs from `Lifecycle().SetOnStarted` on its own goroutine, polling for the handle; every failure is a logged no-op. **Never centre on an assumed size** — doing so put the status bar under the taskbar |
| `nvthreadctl.go` | NVIDIA Threaded Optimization guard — that driver feature corrupts multi-window OpenGL rendering (glyph-streak artefacts in the quiet window while another animates; reproduced with a minimal Fyne app on Fyne 2.7.3–2.8.0, immune to all app-side serialisation, verified on an RTX A6000). `disableNvidiaThreadedOptimization()` (called first thing in `main`, before any GL context) writes `OGL_THREAD_CONTROL = disable` into this exe's driver profile via NVAPI DRS — nvapi64.dll's `nvapi_QueryInterface` by well-known IDs, struct versions validated by the driver. Idempotent, non-fatal on failure, no-op without an NVIDIA driver. Self-test: `DICOMQR_NVAPI_TEST=1 go test -run TestNvapiThreadControlRoundTrip` (writes/deletes a throwaway driver profile) |

Decodable ≠ negotiable here; `TestAcceptedSyntaxesFor` asserts the exclusion |

| `serverprofile.go` | `ServerProfile` struct for saved server connections |
| `ownedwindow.go` | Owned-window helper — Fyne has **no modal windows** (no parent, no modal flag, no transient-for on `fyne.Window`), so panels promoted from dialogs need both an ownership chain and simulated modality. `openOwnedWindow(a, windowSpec, build)` registers parent→children, raises rather than duplicates a keyed window, and cascades closes downward. The cascade hangs off `SetOnClosed`, **not** `SetCloseIntercept` — an intercept fires only for the title-bar button, never a programmatic `Close`. `Blocking: true` pushes a dim `canvas.Rectangle` onto the parent's canvas: Fyne resizes non-popup overlays to the full canvas and, while any overlay exists, routes pointer input to that overlay alone (`driver.FindObjectAtPositionMatching` short-circuits the content roots), which is how its own dialogs feel modal. ## DICOM library policy

**suyashkumar/dicom owns everything application code does with DICOM files** — parsing, writing, presenting. **grailbio/go-dicom is an internal detail of the vendored netdicom stack** (Q/R element plumbing, DIMSE wire encoding, dicomlog) and must never be imported by new application code: it is archived with a pre-2018 data dictionary, so any path that re-encodes through it mistypes newer tags (e.g. 0018,9362 → UN → unencodable). The C-STORE push therefore sends stored dataset bytes verbatim (no parse/re-encode). Remaining grailbio usage (dicomnet.go Q/R elements, storagescp.go meta writer, main.go dicomlog) is contained legacy, **deliberately left in place**: it handles only pre-2018-stable machinery (self-authored query keys, the fixed meta group, mainstream SOP classes), and the Q/R plumbing embodies hard-won field fixes (Conquest negotiation, C-GET message-ID split). Do not migrate it without a concrete trigger — an inexpressible query key, a missing SOP class (fix by adding a UID constant to the vendored fork instead), a grailbio build breakage, or a demonstrated defect.

- `github.com/algm/go-netdicom` — DICOM networking (C-ECHO, C-FIND, C-MOVE SCU, C-STORE SCP/SCU, Worklist); vendored under `thirdparty/go-netdicom` with local patches for `QRLevelPatientStudyOnly`, `QRLevelWorklist`, and `commandset.Init` (now `sync.Once` + `init()`: it calls `tag.Add`, which **writes** the dictionary map every `tag.Find` reads, and upstream called it lazily from `Run`/`NewServiceUser` — a first association concurrent with the tag picker's dictionary probe is a fatal concurrent map read/write)

- `github.com/grailbio/go-dicom` — DICOM dataset encoding used by the C-STORE SCU and SCP
- `github.com/sqweek/dialog` — native Windows file/folder picker
- `modernc.org/sqlite` — pure-Go SQLite (no CGO) for the Local Browse persistent index

## Notes

- App ID: `com.jeffreyleal.dicomqr`
- Settings persisted to `~/.dicomqr/settings.json`
- C-MOVE requires the embedded C-STORE SCP listener (default port 11112) to receive files
- The local AE Title (default `DICOMQR`) must be registered on the PACS as a known destination
- The app "owns" the download folder: downloads, imports, and manual scans keep `.dicomqr-index.db` in sync with the folder contents, and touching a tree entry whose files were removed externally prunes it from both the tree and the index
- Modification (de-identification) profiles live in `~/.dicomqr/profiles.json` with tag aliases in `~/.dicomqr/tags.json`, seeded from `defaults/` on first run and never overwritten by seeding; the format and semantics match dicomtool, so profile files can be copied between the two tools — with three deliberate divergences: `zip` and `transfersyntax` are dicomqr-only (ignored by dicomtool, and dropped when it saves), and dicomtool's `maskrows` is unsupported here (dropped on load, stripped on save). Profiles are managed in Preferences > Modification & Export — changes are written back only on Apply and only when something changed, and a profiles.json that fails to parse is never overwritten. Modified files always go to a user-chosen folder outside the download folder — the catalog is never touched
