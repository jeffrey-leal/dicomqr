# dicomqr

A Fyne-based Windows GUI application for querying and retrieving DICOM files from a PACS server.

## Build

Requires CGO and the mingw64 GCC toolchain. **Must be built from an MSYS2 MinGW64 terminal.**

JPEG 2000 decoding (`-tags openjpeg`) requires the OpenJPEG library, and JPEG Lossless decoding (`-tags jpeglossless`) requires libjpeg-turbo 3.x, each installed once with:
```bash
pacman -S --needed mingw-w64-x86_64-openjpeg2
pacman -S --needed mingw-w64-x86_64-libjpeg-turbo
```
Release builds enable both tags (`-tags "openjpeg jpeglossless"`; libopenjp2 and libjpeg are statically linked — single self-contained exe). Omitting a tag still builds; the corresponding files then report "support not built in" and suggest the external viewer.

All builds must pass `-extldflags=-static` so GCC links its own runtime (libwinpthread, libgcc) statically; without it the exe imports `libwinpthread-1.dll` and fails to start on machines without MSYS2.

Open MSYS2 MinGW64, then:

```bash
export PATH="/c/Program Files/Go/bin:$PATH"
cd /c/Users/jeffr/source/repos/dicomqr
```

Release build:
```bash
CGO_ENABLED=1 CC=/c/msys64/mingw64/bin/gcc.exe GOAMD64=v3 \
  go build -tags "openjpeg jpeglossless" -ldflags="-s -w -H windowsgui -extldflags=-static -X main.buildDate=$(date +%Y-%m-%d)" -o dicomqr.exe .
```

Development build (with debug info):
```bash
CGO_ENABLED=1 CC=/c/msys64/mingw64/bin/gcc.exe \
  go build -tags "openjpeg jpeglossless" -ldflags="-extldflags=-static -X main.buildDate=$(date +%Y-%m-%d)" -o dicomqr.exe .
```

| File | Purpose |
|---|---|
| `main.go` | App entry point, window layout, tab container, menu bar, connection panel, query panel, retrieve panel, status bar, connection/SCP LEDs |
| `resultsmodel.go` | `resultsModel` — tree data structure for C-FIND query results |
| `queryrow.go` | `queryRow` — Fyne widget for results tree rows (hover tooltip, right-click menu) |
| `dicomnet.go` | `DicomClient` — SCU wrapper for C-ECHO, C-FIND, C-MOVE, C-GET, C-STORE, Modality Worklist |
| `storagescp.go` | `StorageSCP` — embedded C-STORE SCP listener that receives C-MOVE deliveries |
| `localbrowse.go` | Local Browse tab — scan download folder, push to PACS, delete local files, preview routing, Modification submenu |
| `catalog.go` | `catalog` — persistent SQLite index (`.dicomqr-index.db` in the download folder) backing the Local Browse tree; nil-safe, WAL, single connection |
| `modifyprofile.go` | Modification (de-identification) profiles — `ModProfile`, load/first-run seeding of `~/.dicomqr/profiles.json`, base-chain resolution, tag parsing/display names. **Every tag reference is canonical `GGGG,EEEE`**: `normalizeModProfile` canonicalises on load, and `mergeModProfiles` compares **parsed tags** (`tagMatchKey`/`setMatchKey`) rather than literal strings — a Keep list cancels its base's Removes by tag identity, so two files spelling one tag differently can no longer silently un-cancel a removal and delete a tag the user asked to preserve. An unparsable reference is kept verbatim for validation to report, never dropped. `validateSetValue` checks a Set value against the tag's VR (dates, times, UIDs, numerics, length limits; empty always allowed) — the engine's `buildElement` only ever coerced the numeric VRs, so a `DA` set to `ANON` used to reach the exported files. A Set value of exactly `[GGGG,EEEE]` is a **reference** to another of the same profile's Set values (`setValueReference`, `resolveSetReferences`, `setValueFollowers`): the shipped profile writes `0010,0020=[0010,0010]` so Patient ID follows the new Patient Name, a relationship the Modification dialog used to hold as hardcoded tag numbers. **A reference can never reach the value in the file being modified** — that would copy the real patient name forward into whatever field named it, per file, with nothing on screen to show it. One level only: a reference to a reference is an error, which rules out cycles by construction. `compileModifyParams` resolves before parsing, so the engine only ever sees literals. `modProfileTargetSyntax` maps the dicomqr-only `transfersyntax` field (same `explicit-le`/`implicit-le` tokens as the server profile) to the UID exports are written in, and the `tsExportLabel*` constants keep the profile editor and the Modification dialog naming it identically |
| `setvalues.go` | `setValueList` — the Set values row list (tag chosen from the picker + value entry + delete), replacing a free-text `TAG=VALUE` box in both profile editors. The owning window is `attach`ed after construction rather than passed in, because both editors build their controls before `openOwnedWindow` creates the window the picker parents to — and keeping construction window-free is what lets `validate()` be driven by tests with no canvas. Choose tags… opens the picker with the current tags checked, so it adds and (by unchecking) removes rows; a tag that stays keeps the value already typed. Rows are sorted by group then element (`sortRows`), with rows whose reference does not parse last — they cannot be ordered and must stay visible to be fixed. A value bracketed like a reference but naming no tag (`[patient name]`) is rejected rather than stored as a literal |
| `modifyengine.go` | De-identification engine ported from dicomtool `modify` (identical semantics): set/remove/keep, DOB mask, UID suffix/remap, date shifting (`shiftdays` — DA/DT at any depth, PatientBirthDate excluded), private-tag removal, fixvr, per-modality overrides; `runModification` worker pool writes to an export folder using the PHI-safe layout from `exportRelPaths` (original patient/study folder names never reused: study runs keep series subfolders only, patient runs get generic `study-NN`); `runModificationToZip` runs the same pipeline into a single zip archive (parallel modify, serialized entry writes; temp-file + rename so a failed/empty run leaves no archive). Two steps have no dicomtool equivalent. An optional **transfer syntax conversion** (`targetTS`), applied **last among the attribute steps** because decompression rewrites the attributes describing the pixels it produces, and profile-wide (never per modality); then **pixel masking** (`maskRegions`, see maskengine.go), which runs after it — masking needs native samples, which the conversion is what produces, and it writes no attribute so the conversion still has the final say over them. `maskingApplies` resolves the regions against the **header** before a frame is decoded, so a file no region applies to is never decompressed — without it, a profile masking a handful of images decompressed and re-encoded the whole study (measured on the 177-file echo study: 23 of every 25 files, a tenfold export, 75 s → 0.1 s for the same 25 files once skipped). It is deliberately generous — unknown dimensions or an unmaskable file return true, so the authoritative per-frame resolution in `applyPixelMask` still runs and still reports the failure. Masking a compressed file that *does* need it **forces a decompression the profile did not request** (there are no encoders, so the alternative is failing every compressed file): the file is written Explicit VR LE and the run counts it in `modifyResult.MaskDecompressed`, which the summary line states — the encoding never changes silently. `mayMask` (profile-level or any override) therefore relaxes the write verification exactly as `targetTS` does. Per-modality mask regions **replace** rather than extend the profile's, since geometry describes one modality's screen layout. A source whose pixel data has no built-in decoder fails that file rather than exporting it in an unrequested syntax. `modifyWriteOpts` relaxes write verification to `SkipVRVerification`+`SkipValueTypeVerification` whenever a conversion is requested — emitting Explicit VR for elements parsed under Implicit VR would otherwise fail files that write fine untouched |
| `maskregion.go` | Pixel-masking regions — `MaskRegion` (the dicomqr-only `maskregions` profile field), validation, and resolution to pixel rectangles. Geometry is stored as **fractions of the image**, never pixels: one study mixes image sizes, and a rectangle measured on the 800×600 loop misses the banner on the 1024×768 capture. Rounding is **outward** (start floors, end ceils) — half a row of leftover text is still PHI. Two modes: `rect`, and `outside-us-regions`, which derives the mask from the file's own `SequenceOfUltrasoundRegions` (the calibrated region is stable where vendor banner geometry is not — the same sequence chapters.go reads). The ultrasound rule uses the **bounding box** of all regions, so a duplex study's two panes keep the gap between them, and counts regions of every data type (no vendor writes identity inside a calibrated region). A file with no such sequence is inert on a non-US modality (so a rule written for the echo series does not fail every CT in the same run); on a **US** file it falls back to the profile's own rectangles when it has any — those files are usually analysis/measurement screens worth keeping, and the banner still goes while the measurements stay — and fails only when there is no rectangle to fall back on. The substitution is never silent: `maskResolution.usFellBack` → `fileNotes.maskUSFallback` → `modifyResult.MaskUSFallback`, a per-file `logWarn`, and a clause in the completion summary, because such a file was masked by geometry measured elsewhere rather than by its own stated layout. An unrecognised mode is always an error — a mask rule that quietly does nothing is indistinguishable, in the export, from a profile that never asked for one. **`MaskScope` (`appliesto`) is how far a region reaches**: nil = every image (what a profile-editor rule means), or any combination of SOP Instance UID / modality / cols / rows / `usregion` (declared\|absent), all ANDed. Added because a rectangle drawn on one analysis screen was applying to the ten beside it *and* to a differently-shaped group — blanking report content the export existed to keep. `maskRects` filters on scope **first**, so a region that does not apply contributes nothing, not even its failure modes. **Scopes resolve against `maskSource`, a snapshot taken in processFile immediately after the parse — never against the live dataset.** Masking runs last, and the steps before it rewrite exactly what a scope keys on: UID remapping (which shipped `base-deident` enables) replaces SOP Instance UID, and a removal rule can delete Modality or the ultrasound region sequence. Resolving live meant every image-scoped region and every exemption silently stopped matching, and the uncalibrated ultrasound files left with nothing applying to them failed and vanished from the export — field-reported. `TestScopedMaskSurvivesUIDRemapping`/`TestExemptionSurvivesUIDRemapping` fail if the snapshot is ever taken later. Third mode `none` records "reviewed, needs no masking": it exists so an ultrasound image with no calibrated region and no applicable rectangle can be exported deliberately rather than failing, without weakening the rule for images nobody has looked at |
| `maskengine.go` | The only code in the application that writes pixel values. `applyPixelMask` mutates each native frame's raw sample slice **in place** — `PixelDataInfo.Frames` holds `*frame.Frame` whose `NativeData` is a pointer, and the writer reads that same slice back, so no element is rebuilt. Native pixel data only: the caller must have decompressed first (see processFile), and encapsulated input is an error rather than a silent skip. Sample indexing follows PlanarConfiguration — the parsing library fills its raw slice sequentially from the stream, so planar data is plane-major and indexing it as interleaved would colour-shift the image instead of blanking it. The fill is **photometric-aware black**, not a constant zero: MONOCHROME1's black is the maximum stored value, YBR_FULL's is `Y=0, Cb=Cr=half`, and PALETTE COLOR resolves the darkest LUT entry — a white or green box reads as an intact annotation rather than a redaction. Chroma-subsampled (`YBR_*_422`/`420`) native data is refused with an instruction to set an output transfer syntax, since its layout is not one triple per pixel. Performance harness: `DICOMQR_MASK_BENCH=<study folder> go test -tags "openjpeg jpeglossless" -run TestMaskBench -v .` reports the study's composition and times three workloads (tags only / one image scoped / every image) so a new modality can be characterised before assuming a cost is inherent. It admits files until their projected **uncompressed** size reaches a budget (2000 MB, `DICOMQR_MASK_BENCH_BUDGET_MB`) — one 240-frame SPECT file alone decompresses to ~500 MB — and always logs how many it left out. It asserts correctness (nothing fails, the scoped image really is masked, at most one file decompressed in the scoped scenario) but never wall-clock thresholds, which only produce flaky failures. **The invariant: if masking was requested and cannot be carried out on a file that has pixel data, the file fails** — exporting it unmasked discloses exactly what the profile existed to remove, and nothing downstream would notice. A dataset with no pixel data is not a failure |
| `maskcanvas.go` | `maskCanvas` — a frame with fractional mask rectangles drawn over it, in the two places a mask must be seen rather than described (picker, preview). All the risk is in `displayArea`: `ImageFillContain` centres and letterboxes, so the image occupies a sub-rectangle of the widget and treating widget coordinates as image coordinates would place a rectangle plausibly on screen and wrongly on export. `fractionAt` clamps, so a drag that strays into the margin still yields a rectangle on the image. `DragEnd` **snaps to the image's pixel grid** — screen coordinates are float32, so an unsnapped drag stores `0.20000000298023224` into profiles.json; snapping also gives the stored fraction a meaning (the area drawn, to the nearest pixel). The drag anchor is captured on the first `Dragged` event, not `MouseDown`, so both ends share one coordinate space — the same lesson `imageViewport` learned with window/level drags |
| `maskpicker.go` | The picker and preview windows. `showMaskRegionPicker` opens a file of the user's choosing (chooser starts in the download folder, threaded through `showModProfileEditor` as `imageStartDir`) and returns the rectangles drawn on it; US-rule rows are never passed in or out, having no geometry to draw. `showMaskPreview` is the **review window** — where masking a real study is actually done, not just checked. `scanMaskGeometryClasses` reads every file's header (`SkipPixelData`, 4 workers, progress) and groups by modality + rows×cols + **whether an ultrasound file declares a calibrated region** (separate classes at identical dimensions: the two are masked by entirely different means, and merging them hides the screens needing a rectangle among the loops needing none), largest group first. **Every file of a class is kept and steppable** — one representative per class was the original design and was wrong: analysis screens share dimensions with nothing else and print text wherever the vendor chose, differing screen to screen. Rectangles are drawn on the displayed image, carry the scope chosen in **Applies to** (`This image only` is the default — widening is always a deliberate act, never an assumption), and go straight into a `maskWorkingSet` (profile-level list plus any override that states its own; `add` follows whichever governs that modality and records the edit, `undo` pops **this session's** stack so it can never start eating regions the profile arrived with, `applyTo` clones `PerModality` rather than writing through). Displayed rectangles are always **`maskRects` itself resolved**, so the window cannot drift from what the export does. Regions apply to the run only — the dialog's standing contract — and `runMasks` in modifydialog.go is what `edited` is built from |
| `maskregionlist.go` | `maskRegionList` — the mask-region row list shared by both profile editors (mode select + four geometry entries + delete, "Add region" below). Geometry is **entered as percentages and stored as fractions**: percentages are what a user can reason about, fractions are what resolves against each frame. `formatPercent` rounds the float noise out of the multiplication (0.29 × 100 = 28.999999999999996) so an unedited profile round-trips to the same numbers. Unlike `setValueList` it opens no window, so it needs no `attach`. `regions()` must return nil (not an empty slice) when the list is empty, for the same reason `strippedTagLines` does — Preferences' DeepEqual change-detection would otherwise rewrite profiles.json on every Apply. Lives in `modProfileFieldSet` rather than on the top-level editor because where an image prints its banner is a property of the modality and the vendor, which is the definition of what a per-modality override may vary |
| `modifydialog.go` | Modification confirmation panel — a **top-level window** (700×700, movable and resizable) opened through `openOwnedWindow`, blocking the main window, deliberately **unkeyed** (blocking already makes a second one unreachable, and two runs on different selections must never collapse into one). It was a dialog until a profile with many set values and a long removal list grew it past the bottom of the screen, putting Modify… and Cancel where they could not be clicked: a Fyne dialog is a canvas overlay sized to its content, with nowhere to scroll. The body now scrolls (240 px floor) with the button row pinned below it. Every child it opens — validation errors, the overwrite confirmations, the mask review window — is parented to `win`, declared at the top of the builder and assigned in the `openOwnedWindow` callback; parenting them to the opener would surface them *behind* the blocked window. The run and failure dialogs stay on the main window, since this one closes as the run starts. Editable set values and options, removal-tag list. Its Options section mirrors the profile editor's **row for row and in the same order** — the two blocks show the same fields and get read against each other, so a differing order is a defect; the one exception is Zip export, which sits in this dialog's Export section beside the output name it changes. Both are built from `prefSection` and share `syncUIDSuffixEnabled`/`uidSuffixRow` for the Remap UIDs / UID suffix pair — they were separate implementations once and the dialog's silently lacked the pairing. export destination (persistent default output folder used directly — picker only when unset, first choice saved as the default, Change… = single-run override, always outside the download folder; editable PHI-safe export folder name pre-filled from the profile's `exportname` (a `[GGGG,EEEE]` reference resolved and sanitized) or else profile + timestamp; a Set row that is a reference shows the resolved value and follows its target as that is typed, until edited directly — the relationship comes from the profile, replacing the hardcoded Patient Name → Patient ID pair whose failure was invisible; Zip export checkbox writes a single `<export name>.zip` instead of a folder and is pre-checked from the profile's `zip` field — per-run override, never written back; Output transfer syntax select is seeded from the profile's `transfersyntax` the same way), background run with progress/cancel/summary. A run that ends with any failed file **replaces** the progress dialog with `showModificationFailureDialog` — files missing from an export are invisible in a summary line, and a conversion that could not run is exactly when the user must know the export is incomplete |
| `modprofileeditor.go` | Modification-profile editor (Preferences > Modification & Export) — a **top-level window** (640×760, movable and resizable; Fyne dialogs are canvas overlays and can be neither), opened through `openOwnedWindow` keyed per profile (so a second Edit raises rather than duplicates) and owned by + blocking the Preferences window, which therefore takes it along when it closes — an orphan would save into a discarded pending map. Single-column layout, sections stacked: name/base, Tag rules, Options, Pixel masking, File filters, per-modality overrides. Pixel masking is its own section rather than an Options row — it is the only setting that alters the image rather than the header, and its caption carries the two consequences (a compressed file is decompressed on export, a file that cannot be masked fails) that have to be read before it is used. Content sits inside a `modEditorMargin` inset (a `layout.NewCustomPaddedLayout` inside the scroll, so the scrollbar still tracks the window edge) — a window gets none of the inner padding a Fyne dialog draws for free, which is what left these controls flush against the frame while the Modification dialog's looked framed. Exposes every engine-honored field: core `ModProfile` fields with validation and base-cycle checks, ignoretype/ignoremodality filters (comma-separated entries), and a per-modality override list whose nested sub-editor edits only the modality-specific fields — the three tag lists plus keepprivate (which is meaningful only there; the top-level flag is inert, so it has no control and is preserved like dicomdir/verbose). Output transfer syntax and Zip export are profile-wide because the engine reads them once per run, not per file. The scalar options (dob/uid/shiftdays/fixvr/noprivate) are profile-wide by product decision even though the engine would honor them per modality — a hand-authored per-modality scalar is preserved and disclosed in the sub-editor's italic note, never silently dropped. The shared `modProfileFieldSet` plus the scalar validators in modifyprofile.go keep validation identical across the main editor, the sub-editor and the Modification dialog; `validate()` on both editor structs is the whole save path, driven directly by tests |
| `tagviewer.go` | Tag-level review window (Local Browse right-click → View Tags) — port of dicomhdr's tag tree: Patient → Study → Series → Instance → elements with search, dictionary hover tooltips, settings-driven styling (private italics, malformed colour, tag profile colours; live-refreshes open windows on preference changes), copy actions, concurrent incremental load, instance right-click Export Tags… (single-instance CSV/JSON via export.go) |

Tags a profile names but the library's dictionary lacks (the shipped base-deident has three) have no row — counted separately by `selectedUnknown` and written back untouched. **Checkboxes on tags only, never groups** (no group wildcard exists in the profile format; whole-group removal would expand to hundreds of entries and destroy 0028/0008); bulk select only over an active search. `mergeTagSelection` rewrites every surviving entry canonically (it used to preserve spellings, back when `mergeModProfiles` compared literal strings); only a line that does not parse at all is kept verbatim, so a typo reaches validation instead of being silently deleted. The name is display only and must never reach profiles.json — `checkTagLines` strips it and stores the canonical reference. `strippedTagLines` must return nil (not an empty slice) or Preferences' DeepEqual change-detection rewrites the file on every Apply |

| `ownedwindow.go` | Owned-window helper — Fyne has **no modal windows** (no parent, no modal flag, no transient-for on `fyne.Window`), so panels promoted from dialogs need both an ownership chain and simulated modality. `openOwnedWindow(a, windowSpec, build)` registers parent→children, raises rather than duplicates a keyed window, and cascades closes downward. The cascade hangs off `SetOnClosed`, **not** `SetCloseIntercept` — an intercept fires only for the title-bar button, never a programmatic `Close`. `Blocking: true` pushes a dim `canvas.Rectangle` onto the parent's canvas: Fyne resizes non-popup overlays to the full canvas and, while any overlay exists, routes pointer input to that overlay alone (`driver.FindObjectAtPositionMatching` short-circuits the content roots), which is how its own dialogs feel modal. Caveat: a parent this helper did not open (the main window) tracks children but gets **no** cascade — installing a close hook would clobber the app's own, and Fyne's `SetOnClosed` replaces rather than chains |
| `preferences.go` | `appTheme` (wraps a colour theme pack, forcing the configured light/dark variant and font), theme pack registry (`themePackBase`: Default / Adwaita / four Catppuccin flavours, persisted as `uiTheme`), system font scanner, tabbed preferences dialog (SCP & Network / User Interface / Modification & Export; Apply copies current settings and overwrites only edited fields) |
| `adwaitatheme.go` | Adwaita colour scheme vendored from fyne-x (BSD-3) — colours only, icons stay stock; vendored because the fyne-x module tracks Fyne master and would silently upgrade the pinned framework |
| `transfersyntax.go` | Transfer syntax UID constants, labels, `fileTransferSyntaxUID` (meta-only parse), and `fileMetaIdentity` (hand-rolled File Meta scan returning SOP class/instance/TS UIDs plus the dataset byte offset — feeds the raw-bytes push) |
| `transcode.go` | Transfer syntax conversion (Explicit/Implicit VR LE targets only — there are decoders but no encoders). `convertDatasetSyntax` is the conversion itself and works on a parsed dataset, so both callers share one implementation: `transcodeDICOMFileToTemp` wraps it in file I/O for the receive path, and `processFile` calls it directly on the dataset a modification has already transformed. Also: `acceptedSyntaxesFor` builds the negotiable set (required first, then locally convertible — other LE VR, JPEG Baseline/Extended, JPEG 2000), and the receive path transcodes any non-required arrival in place before it reaches the download folder; objects that cannot be obtained in the required syntax — whether the server cannot deliver them in a negotiable syntax (failed sub-operations) or a delivered object fails local conversion (e.g. a screenshot with undecodable pixel data) — are skipped and reported (Activity Log + retrieve summary) while the rest of the retrieve continues; only a retrieve where the server delivers nothing at all raises an error dialog |
| `export.go` | CSV and JSON export of a single instance's element list from the tag viewer (right-click an instance row → Export Tags…) — the application's only export; always the complete instance regardless of the search filter, tags formatted `[GGGG,EEEE]` zero-filled 4-digit hex (square brackets, not parentheses — Excel parses `(0020,0001)` as the negative number -20,001; brackets import as text with no formula wrapper needed) |

## DICOM library policy

**suyashkumar/dicom owns everything application code does with DICOM files** — parsing, writing, presenting. **grailbio/go-dicom is an internal detail of the vendored netdicom stack** (Q/R element plumbing, DIMSE wire encoding, dicomlog) and must never be imported by new application code: it is archived with a pre-2018 data dictionary, so any path that re-encodes through it mistypes newer tags (e.g. 0018,9362 → UN → unencodable). The C-STORE push therefore sends stored dataset bytes verbatim (no parse/re-encode). Remaining grailbio usage (dicomnet.go Q/R elements, storagescp.go meta writer, main.go dicomlog) is contained legacy, **deliberately left in place**: it handles only pre-2018-stable machinery (self-authored query keys, the fixed meta group, mainstream SOP classes), and the Q/R plumbing embodies hard-won field fixes (Conquest negotiation, C-GET message-ID split). Do not migrate it without a concrete trigger — an inexpressible query key, a missing SOP class (fix by adding a UID constant to the vendored fork instead), a grailbio build breakage, or a demonstrated defect.

## Notes

- App ID: `com.jeffreyleal.dicomqr`
- Settings persisted to `~/.dicomqr/settings.json`
- C-MOVE requires the embedded C-STORE SCP listener (default port 11112) to receive files
- The local AE Title (default `DICOMQR`) must be registered on the PACS as a known destination
- The app "owns" the download folder: downloads, imports, and manual scans keep `.dicomqr-index.db` in sync with the folder contents, and touching a tree entry whose files were removed externally prunes it from both the tree and the index
- Modification (de-identification) profiles live in `~/.dicomqr/profiles.json`, seeded from `defaults/` on first run and never overwritten by seeding; the format and semantics largely match dicomtool, with four deliberate divergences: `zip`, `transfersyntax`, `exportname` and `maskregions` are dicomqr-only (ignored by dicomtool, and dropped when it saves), dicomtool's `maskrows` is unsupported here (dropped on load, stripped on save — `maskregions` is its replacement, and masks rectangles rather than whole rows from the top), and **tag aliases are gone** — dicomqr no longer reads `tags.json`, so a dicomtool profile referring to tags by phrase (`PatientName=ANON`) must be recoded to `0010,0010=ANON` before it will compile here. The tag picker names tags from the standard dictionary, which made a user-maintained alias map a second naming authority with nothing left to do. An existing `~/.dicomqr/tags.json` is left on disk, inert. Profiles are managed in Preferences > Modification & Export — changes are written back only on Apply and only when something changed, and a profiles.json that fails to parse is never overwritten. Modified files always go to a user-chosen folder outside the download folder — the catalog is never touched
